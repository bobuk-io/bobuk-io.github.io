# bobuk.io — публичные приложения

Статический лендинг на Astro: английский (`/`), русский (`/ru/`) и украинский (`/uk/`). Для каждого языка — адаптивная главная, страницы приложений, поддержки и конфиденциальности. В каталоге Splash Finish, HAScS и Ting — лаунчер для macOS с ведущей клавишей. На сайте показываются только приложения, чья публичность подтверждена GitHub API. HAScS открыт после проверки Git-истории и всех четырёх опубликованных релизов на приватные данные.

Языковой переключатель сохраняет страницу приложения и раздел. Каждая страница имеет свой `lang`, canonical, hreflang (включая x-default) и локализованные SEO-метаданные. Автоматического перенаправления по языку браузера нет: URL стабилен, ссылки работают без JavaScript. У каждого приложения на главной и на его странице — карусель настоящих скриншотов (`src/components/ShotCarousel.astro`): без JavaScript это прокручиваемая лента со snap, скрипт добавляет стрелки, точки, счётчик и навигацию стрелками клавиатуры; автопрокрутки нет. Подписи и alt переведены. Интерфейс Splash Finish и Ting английский во всех языках (на клавишах Ting видна вторая буква активной раскладки, это функция приложения); HAScS снят на языке страницы.

## Обновление сайта

Правила — когда обновлять лендинг после релиза, как объявлять релизы, добавлять приложения, снимать скриншоты и публиковать — в [docs/updating.md](docs/updating.md). Коротко: факты берутся из README и release notes приложения, тексты пишутся сразу на трёх языках, в каталог попадают только публичные репозитории, скриншоты — только настоящие, с демо-данными.

Каталог — `src/data/catalog.json`, тексты приложения — `src/data/apps/<slug>.ts`, скриншоты — `public/images/shots/<slug>/` (lossless WebP). Как они сделаны и как переснять — в разделе «Скриншоты» документа. `public/images/<slug>.png` — PNG-превью для соцсетей.

## Запуск

Node.js 22.23.4+ (рекомендуется актуальный LTS) и npm.

```sh
npm ci
npm run dev
# http://127.0.0.1:4321
```

## Проверка и сборка

```sh
npm run sync:github
npm run build
npm test
npm run preview
```

`sync:github` обращается к публичному API **без токена**, проверяет владельца и видимость и атомарно обновляет `src/data/public-repos.json`. Исключает форки и архивы. Заодно записывает в `updatedAt` дату последнего опубликованного релиза каждого репозитория (без черновиков и пре-релизов; если релизов нет — дату последнего push). По ней главная ставит первым самое недавно обновлённое приложение; при равных датах сохраняется порядок из `src/data/catalog.json`. Если дату релиза получить не удалось (например, из-за лимита анонимных запросов), остаётся прежняя дата из snapshot и деплой не прерывается. Ошибка сети не затирает snapshot и прерывает команду. Контент приватных репозиториев не запрашивается.

Сборка офлайн использует последний snapshot; перед **каждой публикацией** выполняйте sync. Если репозиторий стал приватным, новая сборка после sync уберёт его страницы. Уже опубликованный статический сайт сам по себе не может обнаружить смену видимости: нужен повторный деплой, а при срочном удалении — также очистка CDN-кэша. README и скриншоты включаются только вручную после проверки публичности.

## Добавить приложение

```sh
npm run app:new -- <репозиторий> [--slug <slug>] [--name "<Имя>"] [--icon <png>]   # заготовка, иконка, запись в каталоге
npm run app:shots -- <slug> [--locale ru] [--tight] <снимок.png…>                  # скриншоты → WebP + записи для shots
swift scripts/capture-windows.swift <pid или имя процесса> <префикс>                # снимки окон без системной тени
```

`app:new` принимает только публичный репозиторий `bobuk-io` и создаёт тексты с метками `TODO(landing)`. Пока они не заменены на всех трёх языках и пока у приложения меньше трёх скриншотов, `npm test` не проходит. Пошагово — [docs/updating.md](docs/updating.md), раздел «Новое приложение». Страницы создаются автоматически маршрутом `src/pages/[...route].astro`. `appStoreUrl` в `catalog.json` необязателен: только реальная опубликованная ссылка.

## Деплой

Сайт: **https://bobuk-io.github.io/**. Репозиторий: [bobuk-io/bobuk-io.github.io](https://github.com/bobuk-io/bobuk-io.github.io).

GitHub Actions (`.github/workflows/pages.yml`) проверяет публичность репозиториев, собирает и тестирует сайт, затем публикует `dist/` в Pages. Запуск — при push в main, вручную и ежедневно в 05:23 UTC. Если GitHub API недоступен, деплой прервётся, последняя опубликованная версия останется доступна. Срочные изменения видимости требуют ручного запуска workflow.

Для другого хостинга подойдут Cloudflare Pages, Netlify, Vercel static или любой HTTPS-хостинг:

- Корень проекта: `landing` (если весь родительский каталог — репозиторий хостинга) или `.` для отдельного репозитория.
- Install: `npm ci`.
- Build: `npm run sync:github && npm run build && npm test`.
- Output: `dist`.
- Установите `SITE_URL=https://ваш-домен` **до сборки**. Значение по умолчанию — `https://bobuk-io.github.io`. Домен bobuk.io не подключён; его DNS не меняется.
- Нужен хостинг из корня домена, не подпапки. Canonical, robots, sitemap и OG используют SITE_URL.
- Настройте 404 на `404.html`; не используйте SPA-rewrite всех запросов на главную.
- При переименовании продукта сохраните старые URL через 301/308 (на GitHub Pages — не меняйте slug).

Клиенту не нужны API, ключи, база данных или аккаунт. Шрифты системные, изображения локальные, сторонние скрипты/аналитика не подключены. Технические логи зависят от выбранного хостинга.
