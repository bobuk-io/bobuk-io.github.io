# bobuk.io — публичные приложения

Статический лендинг на Astro. Русский интерфейс, адаптивная главная, страницы приложения, поддержки и конфиденциальности. На момент проверки в bobuk-io публичен только Splash Finish. Соседние локальные проекты не использованы.

## Запуск

Node.js 22.23.4+ (рекомендуется актуальный LTS) и npm.

```sh
npm ci
npm run dev
# http://127.0.0.1:4321
```

## Проверка и сборка

```sh
npm run sync:github
npm run build
npm test
npm run preview
```

`sync:github` обращается к публичному API **без токена**, проверяет владельца и видимость и атомарно обновляет `src/data/public-repos.json`. Исключает форки и архивы. Ошибка сети не затирает snapshot и прерывает команду. Контент приватных репозиториев не запрашивается.

Сборка офлайн использует последний snapshot; перед **каждой публикацией** выполняйте sync. Если репозиторий стал приватным, новая сборка после sync уберёт его страницы. Уже опубликованный статический сайт сам по себе не может обнаружить смену видимости: нужен повторный деплой, а при срочном удалении — также очистка CDN-кэша. README и скриншоты включаются только вручную после проверки публичности.

## Добавить приложение

1. Сделать репозиторий публичным в `bobuk-io`, выполнить `npm run sync:github`.
2. Добавить запись в `src/data/apps.ts` и публичные изображения в `public/images/`.
3. Адаптировать product/support/privacy контент в `src/pages/apps/[...path].astro`: сейчас он специально написан для Splash Finish, не является универсальной политикой для всех приложений. До добавления второго приложения вынести этот текст в контент конкретного продукта.
4. Проверить факты, требования, privacy, изображения и ссылки. Выполнить build и test.
5. `appStoreUrl` необязателен: используйте только реальную опубликованную ссылку.

## Деплой

Сайт: **https://bobuk-io.github.io/**. Репозиторий: [bobuk-io/bobuk-io.github.io](https://github.com/bobuk-io/bobuk-io.github.io).

GitHub Actions (`.github/workflows/pages.yml`) проверяет публичность репозиториев, собирает и тестирует сайт, затем публикует `dist/` в Pages. Запуск — при push в main, вручную и ежедневно в 05:23 UTC. Если GitHub API недоступен, деплой прервётся, последняя опубликованная версия останется доступна. Срочные изменения видимости требуют ручного запуска workflow.

Для другого хостинга подойдут Cloudflare Pages, Netlify, Vercel static или любой HTTPS-хостинг:

- Корень проекта: `landing` (если весь родительский каталог — репозиторий хостинга) или `.` для отдельного репозитория.
- Install: `npm ci`.
- Build: `npm run sync:github && npm run build && npm test`.
- Output: `dist`.
- Установите `SITE_URL=https://ваш-домен` **до сборки**. Значение по умолчанию — `https://bobuk-io.github.io`. Домен bobuk.io не подключён; его DNS не меняется.
- Нужен хостинг из корня домена, не подпапки. Canonical, robots, sitemap и OG используют SITE_URL.
- Настройте 404 на `404.html`; не используйте SPA-rewrite всех запросов на главную.
- При переименовании продукта сохраните старые URL через 301/308.

Клиенту не нужны API, ключи, база данных или аккаунт. Шрифты системные, изображения локальные, сторонние скрипты/аналитика не подключены. Технические логи зависят от выбранного хостинга.
